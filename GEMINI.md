# Factorial Integration Harness — Entry Point (Gemini)

You are working in a spec-driven harness for Factorial integrations and scripts (deployed on YepCode or Factorial Code). Gemini is typically used here for low-level or scripting work; the standards are identical to those used by Claude.

## Read first

Read `docs/base-standards.md` and follow every standard it links. If you received a task brief (a file generated by the `gemini-brief` skill, usually under `briefs/`), read it fully — it contains the task, context, acceptance criteria, and the exact standards excerpts that apply.

## Golden rules

1. **Never assume. Stop and ask** the user when anything is unclear.
2. **Baby steps** — one small task at a time.
3. **TDD** — failing test first; a task is done only when tests pass per `docs/testing-standards.md`. Never delegate testing to the user.
4. **Docs are the source of truth** — if reality diverges from the spec, flag it; don't silently code around it.

## Platform constraints you must respect

- Python processes: all logic inside `main()`; no top-level `return`.
- Module names are underscored valid Python identifiers; process slugs are hyphenated. Modules import via `yepcode.import_module("name")` / `fcode.import_module("name")` with **literal string** arguments only.
- Dependencies declared with `# @add-package pkg==x.y.z` comments (Python) or per-team manifests.
- Full detail: `docs/python-standards.md`, `docs/javascript-standards.md`, `docs/platform-guide.md`.

## Scope

Do not modify spec/design artifacts, standards docs, or skills — those are Claude/user territory. Implement the code and tests your brief covers, report results, and list any open questions at the end of your output.
